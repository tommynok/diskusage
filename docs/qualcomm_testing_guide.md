# Руководство по тестированию DiskUsage на устройствах Qualcomm Snapdragon

## 1. Особенности архитектуры разделов Qualcomm (Snapdragon)

В современных смартфонах на процессорах Qualcomm Snapdragon (Android 10–15) файловая система организована следующим образом:

1. **Динамические разделы (Dynamic Partitions / `super`):**
   * `/system` — основная ОС Android
   * `/vendor` — проприетарные HAL-модули и службы Qualcomm
   * `/product` — сервисы и приложения производителя / Google
   * `/system_ext` — расширения платформы Android
   * `/odm` — конфигурации сборщика устройства
   * Все эти разделы обычно упакованы в динамический контейнер `super` (файловые системы `erofs` или `ext4`).

2. **Специфические разделы Qualcomm Firmware (подмонтированы внутри `/vendor`):**
   * `/vendor/firmware_mnt` — образ модема / радиомодуля (baseband / modem, обычно `vfat`).
   * `/vendor/dsp` — микрокод процессоров Hexagon DSP / ADSP / CDSP / SLPI (обычно `ext4` или `vfat`).
   * `/vendor/bt_firmware` — прошивка модуля Bluetooth (`vfat`).
   * *Примечание:* Фильтр DiskUsage специально сохраняет эти три пути, отсекая случайные bind-файлы.

3. **Служебные разделы калибровки и NVRAM:**
   * `/mnt/vendor/persist` (или симлинк `/persist`) — раздел заводских калибровок (Wi-Fi/Bluetooth MAC-адреса, калибровки сенсоров, ключи Widevine DRM).
   * `/metadata` — раздел криптографических метаданных FBE-шифрования.
   * `/efs`, `/sec_efs`, `/carrier` — разделы EFS/IMEI на смартфонах Samsung Snapdragon.

4. **Системный шум (автоматически отсекается в DiskUsage):**
   * 40–70 loop-монтирований APEX-пакетов (`/apex/...`)
   * Виртуальные псевдо-ФС (`/proc`, `/sys/fs/cgroup/*`, `selinux`, `bpf`, `devpts`, `binder`)
   * FUSE-зеркала прав Android 11+ (`/mnt/installer/*`, `/mnt/androidwritable/*`, `/mnt/user/*`, `/mnt/pass_through/*`)
   * Одиночные bind-mounts файлов из модулей Magisk / KernelSU (`/system/etc/hosts`, файлы ReVanced и т.п.).

## 2. Быстрая диагностика через ADB (без установки или с установкой)

`/proc/mounts` в Android имеет права `0444` (`r--r--r--`), поэтому его можно прочесть **даже без root-прав через стандартный ADB shell**.

### Вариант А: Запуск скрипта симулятора (рекомендуется)
Подключите телефон по USB с включенной отладкой по ADB и запустите:
```bash
python tools/simulate_mounts.py
```
Скрипт сам выполнит `adb shell cat /proc/mounts`, пропустит точки монтирования через фильтр DiskUsage и выведет:
* Общее число точек в системе
* Список отфильтрованного мусора
* Разделы, которые попадут в показ по умолчанию (`/`, `/data`, `/system`, `/vendor`, `/product`)
* Опциональные разделы в «Настройке видимых разделов» (например, `/vendor/firmware_mnt`, `/mnt/vendor/persist`).

### Вариант Б: Ручной сбор данных через ADB
1. **Снять список точек монтирования (root не требуется):**
   ```bash
   adb shell "cat /proc/mounts" > qualcomm_mounts.txt
   ```
2. **Снять список физических блочных устройств (с root):**
   ```bash
   adb shell "su -c 'ls -la /dev/block/by-name'" > qualcomm_block_devices.txt
   ```
3. **Проверить скриптом снятый файл:**
   ```bash
   python tools/simulate_mounts.py qualcomm_mounts.txt
   ```

## 3. Чеклист тестирования APK на Qualcomm

При передаче APK тестеру проверить следующие сценарии:

1. **Первый запуск (чистый экран):**
   * Открыть DiskUsage.
   * Должны отображаться:
     1. `Память устройства`
     2. `Карта памяти` (если вставлена MicroSD / USB-OTG)
     3. `[Требуются root-права]`
2. **Раскрытие root-разделов:**
   * Нажать `[Требуются root-права]`.
   * Должен аккуратно раскрыться базовый набор:
     * `/` (корень)
     * `/data` (пользовательские данные)
     * `/system` (система)
     * `/vendor` (драйверы Qualcomm)
     * `/product` (приложения прошивки)
     * `[Показать/скрыть]`
   * В списке **НЕ ДОЛЖНО БЫТЬ**: `/apex/...`, `/proc`, `/sys`, `/dev`, `/storage/emulated/...`, `/data/user/0`.
3. **Меню «Настройка видимых разделов»:**
   * Нажать `[Показать/скрыть]`.
   * Список должен содержать только реальные разделы (~8–12 пунктов).
   * По умолчанию включены: `/`, `/data`, `/system`, `/vendor`, `/product`.
   * Попробовать включить, например, `/vendor/firmware_mnt` или `/mnt/vendor/persist` и вернуться назад — выбранный раздел должен появиться в главном меню выбора.
   * Проверить кнопки меню: «Снять все», «Выбрать все», «Только основные».
4. **Сканирование:**
   * Выбрать `/data` — проверить, что сканирование отрабатывает через нативный root-бинарник и разворачивает дерево каталогов (`/data/app`, `/data/data`, `/data/media/0` и т.д.).
   * Выбрать `/vendor` — проверить корректность отображения структуры Qualcomm HAL.
